# 5스테이지 해금 / 6·7스테이지

## 로비 진행

5번 버튼은 `Stage05`를 사용합니다. 이전 `StageHero` / `Stage_Hero` 버튼 설정도
실행 시 `Stage05`로 교정합니다. 캠페인 해금은 4 → 5 → 6 → 7 순서입니다.

## 6스테이지

맵: `/Game/Game/Stage/PT_SFStageAmbush`

- 플레이어 에테리안, 적 비스트. 중앙 방어 구역에 본진·근접/원거리 생산·주거 2개·광물/에테르 광산을 배치했습니다.
- 세 숲길에서 총 5웨이브. 첫 웨이브와 이후 웨이브 모두 준비 60초, 방어 300초입니다.
- 예정 적을 모두 생성·처치해도 300초를 채웁니다. 5번째 방어 시간 종료 시 승리하며 본진 파괴 시 패배합니다.
- 3스테이지와 같은 총수량 14 / 22 / 29 / 36 / 43, 티어 가중치 5:3:1을 사용합니다.
- 근접 Brawler / Berserker / Predator, 원거리 Hunter / Stalker / ApexHunter. 특수 유닛은 제외합니다.
- 기존 자원 8곳의 매장량을 광물 각 3,000, 에테르 각 1,800으로 조정했습니다.
- 시작 자원은 `DT_SFStage.Stage06`: 광물 2,000 / 에테르 800입니다.
- 기존 Ambush Director는 로딩·다리 연출을 유지하며 웨이브 컨트롤러가 있을 때 자체 생존 승리를 실행하지 않습니다.

## 7스테이지

맵: `/Game/Game/Stage/PT_SFStageFinal`

로비에서 7스테이지를 누르면 에테리안/비스트 선택 창이 열립니다. 돌아가기를 누르면
진입하지 않으며, 재시도는 선택했던 종족을 유지합니다.

`DT_SFStage.Stage07`의 `PlayerRace=None`, `Use Faction Bases=true`가 선택 모드를 설정합니다.
맵 편집 시 **팀 0은 에테리안 자리, 팀 1은 비스트 자리**입니다.
런타임에 선택한 진영을 플레이어 팀 0으로, 다른 진영을 적 팀 1로 바꿉니다.
건물 앵커·진격로·스포너의 팀을 함께 바꾸고 카메라를 선택한 본진으로 이동합니다.

각 진영은 본진, 근접/원거리 생산 건물, 주거 2개, 광물/에테르 광산으로 시작합니다.
본진과 생산 건물은 2티어입니다. 플레이어 생산은 기존 생산 UI를 사용합니다.
적 생산 건물은 근접 30초/원거리 40초 간격으로 병력을 보내며 건물별 생존 상한은 6기입니다.
생산 건물이 파괴되면 해당 자동 생산이 멈춥니다. 적 본진 파괴 시 승리합니다.
시작 자원은 DT에 광물 1,500 / 에테르 600으로 설정했습니다.

## 설정 및 검증

### 6스테이지 시점과 최종전 스토리

6스테이지는 세 갈래 진입로가 화면 위를 향하는 정면 시점(카메라 Yaw 0)으로 시작합니다.
시작 카메라 거리는 다른 스테이지의 공통 카메라와 같은 1,600입니다.
줌 범위 1,000~3,000과 기울기 -55도도 공통값을 사용하며 미니맵 회전은 정면 방향입니다.
신규 건물 배치 방향은 기존 건물에 맞춰 90도로 설정했습니다.

`ContentSource/Stage67Story_KO.json`의 원고를 `DT_SFStageIntro`에 저장했습니다.
6스테이지는 `Stage06` / `Stage06Clear`, 최종전은 선택한 종족에 따라
`Stage07_Human` / `Stage07_HumanClear` 또는 `Stage07_Beast` / `Stage07_BeastClear`를 사용합니다.
Human은 에테리안의 내부 식별자입니다. 시작 이야기가 끝나면 플레이를 시작하고,
승리 후일담을 끝까지 읽은 뒤 결과 화면을 표시합니다.

`ContentSource/Stage67StoryPortraits.json`은 장면별 커맨더 표정과 강조 방향을 지정합니다.
에테리안 대주교는 왼쪽, 비스트 지휘관은 오른쪽에 기존 스토리 이미지를 표시합니다.
6스테이지 함정 장면은 두 인물을 함께 보여 주고, 최종전과 엔딩은 해당 진영의 커맨더를 중심으로 진행합니다.
에디터 플레이의 K키 즉시 승리는 3·5·6·7스테이지에서 동작합니다.
시작 스토리 중에도 사용할 수 있으며, 정상 승리 후일담을 거쳐 결과 화면으로 이동합니다.

`Scripts/Editor/configure_stage67_story.py`는 위 설정만 적용하며 기존 건물·지형 배치를 보존합니다.
`StrikeForge.Campaign.Stage67Stories`는 이야기 분기와 노드 연결을 검사합니다.
`Scripts/Editor/verify_stage67_story_runtime.py`에 `-Stage67StoryCase=6`, `Human`, `Beast`를 전달하면
PIE에서 실제 선택된 원고, 각 문단의 커맨더 이미지, 카메라 거리, K키 승리,
일시정지/재개, 후일담 후 결과 화면을 검사합니다. 비스트 분기는 시작 이야기 재생 중 K키도 검사합니다.
렌더링 실행에 `-Stage67Capture`를 추가하면 이야기 화면도 캡처합니다.
결과와 변경 전 백업은 `Saved/Stage67Story`에 저장합니다.

`Scripts/Editor/configure_stage67.py`는 변경 전 패키지를 `Saved/Stage67/before_*`에 백업하고
위 설정을 저장합니다. 지형·장식은 보존하며, 재실행 시 스크립트가 추가한 건물만 다시 배치합니다.

- `StrikeForge.Campaign.ProgressAndRaceChoice`: 실제 DT/로비 연결, 순차 해금, 두 종족 선택.
- `StrikeForge.Defence.WaveFlow`: 기존 3스테이지 동작과 6스테이지의 60초/300초 5웨이브.
- `Scripts/Editor/verify_stage67_runtime.py`: `-Stage67Case=6`, `Human`, `Beast`로 PIE 검증.
  결과는 `Saved/Stage67/runtime_*.json`에 저장됩니다. 화면 없는 검증에서만 로딩 페이드를 건너뛰며,
  6스테이지 후반 웨이브는 테스트 인스턴스에서 시간을 줄여 검사합니다. 저장된 맵 시간은 변경하지 않습니다.
